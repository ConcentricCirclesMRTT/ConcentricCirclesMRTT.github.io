NEUBE-STRUCTURAL-REBUILD · 2026

两种工作方式

黑盒生成交付一个结果。
NeuBE 交付一个可以继续工作的结构。

01
一次性三维生成ONE-SHOT GENERATION
图纸 / 图片→等待→最终模型
  • 适合概念草图与快速预览
  • 局部错误往往需要整体重新生成
  • 无法回答构件来自哪里、为何这样连接
  • 最终文件缺少稳定身份与工程关系
02
NeuBE 结构重构STRUCTURAL RECONSTRUCTION
工程资料→结构项目↻持续工作
  • 输出仍然是一个可读写的工程项目
  • 局部构件、关系与判断可以单独修正
  • 证据、身份、约束和版本持续保留
  • 结果可以进入 CAD、数字孪生与后续 Agent

差别不在模型看起来多漂亮。 差别在于结果能否被追问、修正、验证，并在下一轮工程工作中继续存在。

02 · 一次性生成 vs. 结构项目

图纸建模 · 完整塔头

让 AI 读工程图纸，
重建结构准确的三维几何

→

从工程图纸读取尺寸、标注和构件关系。 通过几何求解与结构核验，形成可检查、可交互的塔头三维模型。

03 · 工程图纸 → 完整塔头三维几何

长上下文建模 · M1–M6 完整塔架

多页、多视图、多模块，
仍然重建成同一个结构。

跨页证据连续，跨视图身份一致，跨模块装配闭合。 M1–M6 分段连接、共享节点和模块依赖最终进入同一个结构模型。

04 · 多页 · 多视图 · 多模块

为什么这对 Agent 更重要

Agent 不再反复抽奖，
而是在同一个结构项目里工作。

只会调用生成接口的 Agent，遇到错误只能重新生成。NeuBE 让 Agent 读取当前结构、执行确定性的工程动作，再把结果写回同一个项目。

01 · READ读取当前结构项目

读取来源、构件身份、连接关系、未决判断和当前版本，而不是从空白 Prompt 重新开始。

→
02 · ACT执行工程动作

调用几何求解、CAD、领域规则与确定性验证器，对明确范围内的结构进行修改。

→
03 · WRITE BACK写回同一个项目

把新几何、关系、验证结果和版本状态写回，让下一位工程师或 Agent 接着工作。

一次可验证的重构序列来源→观察→结构身份→约束验证→版本化输出

05 · READ → ACT → WRITE BACK

你仍然拥有控制权

Agent 完成重构，
但结构仍然属于你。

每一次变化都能回到它的来源、判断与版本。人可以继续检查、修正和移交，而不是被锁在一次黑盒输出里。

01可见VISIBLE

知道构件来自哪张图、哪个区域。

02可修改EDITABLE

单独修正构件、关系或候选判断。

03可验证VERIFIABLE

约束、残差和验证结果保持可见。

04可移交PORTABLE

交付模型、结构数据和版本化制品。

来源 / 原始观察

原始输入不被解释覆盖

保存图纸版本、页码、局部区域和原始字符串。当前状态只说“看到了什么”，不急于说“它是什么”。
